## 2. 差距分类（用于合并同类任务）

| 差距类型 | 判定依据 | 处理建议 | 是否需要 web-control |
|---|---|---|---|
| G1 缺后端 Controller | 前端 API 返回 `No static resource` | 后端补 Controller/Service/Mapper（另派/另排期）或 C++ 端本地化 | 联调时需 8080 重启 → 申请 |
| G2 缺数据库表/字段 | SQL 异常 `Table 'zzyl.x' doesn't exist` 或字段为空 | 补 DDL/种子数据（写库 → 申请） | 写库 → 申请 |
| G3 前端页面/弹窗缺失 | 菜单有、views 无对应组件 | 新建页面（按已有同类页面模板） | 需 88 + 浏览器 → 申请 |
| G4 菜单/路由缺失 | 有页面无 sys_menu / 无路由（404） | 补菜单（写库）或改静态路由 | 写库 → 申请 |
| G5 交互/校验缺陷 | 实测与预期不符（如只读仍显示提交、区间显示错误） | 缺陷修复单 | 联调需 88 → 申请 |
| G6 数据质量 | 脏数据/空值/枚举不一致 | 数据清洗脚本（写库 → 申请） | 写库 → 申请 |
| G7 文档/契约 | UI 或数据契约变化影响 C++ | 更新 `docs/architecture/*` | 否（免申请） |

**拆单规则**：
1. 写作用域必须互斥（同一文件/目录只分配给一个 owner）；跨文件共享改动由 web-arch 先拆出“公共层任务”排在前面。
2. 每个任务必须有**可测验收标准**（能写成一条用例）。
3. 标注是否需要 web-control 申请（重启/浏览器/写库）；免申请任务（前端代码、文档、编译）不占调度资源。
4. 依赖关系写清“前置任务号”；后端缺口任务与前端任务解耦（前端可先 mock/本地种子）。

## 4. 依赖与排期

```
后端/数据先行任务（BE/DB） → 前端列表/表单任务（FE） → 联调（需 web-control） → 测试验收
                     ↘ 可并行的纯前端任务（不依赖后端）→ 直接 FE
```

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| M0 盘点完成 | 功能盘点表填满、差距分类完成 | lead 确认范围 |
| M1 拆单完成 | 任务单全部落表、owner/依赖/验收明确 | lead 确认排期 |
| M2 开发完成 | 前端实现 + 自测 | 无 P0/P1 缺陷 |
| M3 联调/验收 | web-tester 用例通过 | 截图/录屏佐证（走申请） |

---

## 5. 验收标准写法模板

- 列表：进入页面 X 秒内加载完成；数据条数 = 种子 M 条；表格列 = 文档 N 列；状态标签颜色正确。
- 搜索：输入/下拉 → 搜索结果符合；重置 → 条件清空并回到第 1 页。
- 表单：必填校验逐项拦截（含提示文案）；提交成功 toast；失败提示错误原因；前后端字段一致。
- 弹窗：宽高/布局/按钮位置与 `docs/architecture` 规格一致；只读态不出现可编辑控件/提交按钮。
- 权限：无权限账号看不到按钮/菜单（v-hasPermi）。
- 环境：联调前确认 88/8080 可用（web-control 调度窗口内）。

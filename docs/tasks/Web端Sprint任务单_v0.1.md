## 1. 角色与协作链路

| 角色 | Agent | 职责 |

## 2. 共享环境调度纪律（摘要，2026-11-25 起强制）

### 2.1 必须申请（先批准后操作，按提交时间 FIFO）

| 资源 | 操作 | 说明 |
|---|---|---|
| 后端 8080 | 重启 / 开关 | 影响所有联调方；默认最长 10 分钟，排队等待 8 分钟 |
| 前端 88 | 启动 / 重启 / 停 | Vite dev 服务 |
| 浏览器自动化 | 无头/有头浏览器、CDP、截图/录屏 | 含 Playwright/CDP/Edge headless |
| MySQL 写操作 | 测试数据增删改 | 只读查询不受限（不影响他人） |

**申请单必填**：申请者 / 目的 / 资源 / 预计时长 / 影响范围 / 是否重启。
**同资源同一时刻仅 1 人**；默认占用 10 分钟，若需排队则最多等 8 分钟；**结束后必须发「释放」**。
**调度日志**：`docs/test/web_调试调度日志.md`（由 web-control 维护，申请/批准/释放均登记）。

### 2.2 免申请（可直接执行）

- 只读代码分析（读源码、grep、静态查看）
- `npm run build`
- `mvn -DskipTests compile`
- 静态检查 / lint / 文档编写（`docs/`）
- 只读 SQL 查询（SELECT，不写库）

### 2.3 禁止

- 未经 lead 明确要求，**重启/停止主人的稳定服务**（88/8080/3306/6379）。
- 按进程名批量杀进程（`taskkill /IM node.exe` 等）；只能按 **PID + 路径确认归属** 后精确停止。
- 未经批准占用共享浏览器/端口做长时间操作。
- 向调度日志或规则文档写入非本人内容（这两个文件归 web-control 维护）。

### 2.4 申请 / 释放模板（复制使用）

```
【申请】web-arch / 目的：Sprint5 功能盘点截图 / 资源：浏览器自动化（无头 Edge 9599）+ 前端 88（只读访问）/ 预计时长：10 分钟 / 影响范围：无重启、无写库，仅读取页面 / 是否重启：否 / 开始时间：____
【释放】web-arch / 资源同上 / 结束时间：____ / 结果：截图 N 张已存 docs/... / 备注：无
```

> 若需 MySQL 写测试数据：额外注明“库名/表名/写入条数/回滚方案”，批准后执行并在释放时说明清理结果。

### 2.5 本人在 Sprint 5 的调度执行 SOP

1. 需要浏览器/端口 → 先向 `web-control` 发申请（模板见 §2.4），**未批准不动手**；
2. 批准后按申请范围操作；超时前未完成 → 发「续期申请」；
3. 结束立刻发「释放」，并在 §7 申请流水登记；
4. 只读代码/文档/编译类工作不申请；
5. 不代替他人申请，不批量杀进程，不重启主人服务。

## 3. Sprint 5 Web 端功能追加流程（收到功能清单后执行）

```
① 接收功能清单（lead 下发）
   ↓
② 功能盘点（web-arch，只读）：逐项核对 现有页面/路由/菜单/API/DB 表/当前状态 ✅⚠️❌
   ↓ 产出《功能盘点表》（模板见 docs/tasks/Web功能盘点与拆单模板_v0.1.md）
③ 差距分析：缺接口 / 缺表 / 缺页面 / 缺菜单 / 交互缺失 / 文档已有规格可复用
   ↓
④ 拆单：按“一个页面/一个弹窗=一个任务”拆分，标注依赖与写作用域
   ↓
⑤ 提交 lead 确认范围与优先级 → 分配给 web-dev1/2/3（写作用域互斥）
   ↓
⑥ 开发联调（涉及 88/8080/浏览器 的操作走 web-control）
   ↓
⑦ web-tester 验收 → 缺陷回流 → lead 验收
```

**盘点口径（必须逐项填）**：页面/路由 → 菜单来源（sys_menu） → 现有实现文件 → 当前状态（✅/⚠️/❌，引用 `Web功能清单_v0.2.md` 已有结论） → 依赖 API（实测状态） → 依赖 DB 表（存在/缺） → 与 C++ 端契约影响（是否有 UI 规格/数据契约需要同步）。

**拆单口径（任务单最小集）**：任务编号 / 标题 / 类型（新功能/修复/数据/UI）/ 涉及文件与写作用域 / 接口与字段 / 涉及表 / 依赖任务 / 验收标准（可测） / 需要哪个环境资源（是否需 web-control 申请） / owner。

# Web 端 · 调试资源调度规则（v1.1）

> **调度员**：web-control（Web 调试子控制中心）。
> **配套日志**：`docs/test/web_调试调度日志.md`（DQ 调度记录 / V 违规记录 / 事件时间线 / 收工摘要）。
> **建立**：2026-11-25 08:47（与 C++ 端 cpp-control 协议对齐）｜**修订**：2026-11-25 08:49（v1.1，lead 确认口径）｜**维护**：web-control。

## 一、目的与职责边界

**目的**：Web 团队（web-arch / web-dev1 / web-dev2 / web-dev3 / web-tester）共享同一台机器、同一组端口，必须串行使用排他资源，避免"多人抢同一端口/服务/浏览器"导致调试互相踩踏。

**web-control 只做**：登记、FIFO 仲裁、批准与回收、核查占用、记录与上报 lead。
**web-control 不做**：不写业务代码、不改前端/后端源码、不 commit、不装依赖、不做 bug triage（triage 归 web-arch）、不重启主人（用户）的常驻服务。

**所有 Web 团队成员与临时协作者**都必须遵守本规则；违反按 §五 处理。

## 二、资源定义与排他粒度

| # | 资源 | 载体/端口 | 排他粒度 | 说明 |
|---|---|---|---|---|
| R1 | **前端 88** | Vite dev server（node.exe / `vite.js`） | 独占"启停 / 重启 / 配置变更"时刻 | 常态运行；HMR 下改前端源码**免申请**；首次启动、端口冲突、`npm install`、改 `vite.config.*` 需申请 |
| R2 | **后端 8080** | Spring Boot（java.exe / `com.zzyl.RuoYiApplication`） | 独占"启停 / 重启 / 稳定窗口"时刻 | 带 `spring-boot-devtools`：**后端编译会触发自动热重启**（约 3–15 秒 8080 不可用）；需要 8080 长时间稳定（联调/自动化测试）时申请 |
| R3 | **浏览器自动化 / 截图** | Edge / Chrome / Playwright / 无头浏览器 / 截图脚本 | 独占**整个自动化会话** | 同一时刻只允许 1 人；开窗口、批量截图、脚本跑页面都算一次会话。人工看一眼页面（不自动化）不算 |
| R4 | **MySQL 写操作** | 127.0.0.1:3306（`zzyl` 库） | 独占"写事务窗口" | 仅**测试数据**；`INSERT/UPDATE/DELETE/建表/改表/改数据` 都算；**演示/生产数据改动必须先报 lead** |
| R5 | 只读 / 自检（免申请） | 端口探测、进程核查、日志查看、只读 SQL、只读代码分析 | 不排他 | 随时可做 |
| R6 | 构建 / 静态检查（免申请） | `npm run build`、`mvn -DskipTests compile`、lint、类型检查 | 不排他 | 不占端口；但见 §2.2 轻量报备 |

### 2.2 轻量报备（不占队列、不需批准，但必须说一句）

以下操作虽免申请，但会"扰动"公共资源，执行者须**开始前、结束后各发一句话**给 web-control（或团队群）：
1. **后端代码编译 / IDEA Build**（`mvn compile`、IDEA 增量编译）→ 会触发 8080 devtools 热重启，正在联调/测试的人会看到 8080 抖动；
2. **前端 `npm install` / 改 vite 配置** → Vite 会自动重启 88；
3. 任何会占用大量 CPU/磁盘导致他人调试变慢的批量任务（大构建、全量测试）。

> **lead 口径确认（2026-11-25 08:49）**：后端编译/IDEA Build 一律走**轻量报备（不占队列）**；只有「需要长时间稳定窗口 / 主动重启 / 前后端联动验收」才正式申请排他窗口。

### 2.3 默认不动的资源与重启执行人

- **3306 MySQL / 6379 Redis 是主人环境**：不重启、不改配置、不 kill；只做只读查询与测试数据写（写需申请）。
- **88 / 8080 是主人/上一轮遗留的常驻服务**（88→PID 35760、8080→PID 23192，见日志核对表）：**默认不重启、不停止**。按 lead 2026-11-25 08:49 口径：
  - 重启**默认由申请人本人执行**（如改完后端代码自己重启并验证），须按 §三 申请窗口，web-control 登记窗口并核查结果；
  - 若涉及**主人 IDEA 稳定实例**（88 PID 35760、8080 PID 23192）的重启/停止，**必须先报 lead 批准**，批准后由 lead 指定执行人执行，web-control 记录在案。

## 三、申请协议

### 3.1 申请格式（send_message 给 web-control）

```
申请者 | 目的 | 需要资源(前端88/后端8080/浏览器/MySQL写) | 预计时长(≤15分钟) | 影响范围 | 是否涉及重启
```

示例：
```
web-dev1 | 新增护理项目页 CRUD 浏览器实测截图 | 浏览器 + MySQL写(护理项目测试数据) | 8 分钟 | 仅测试库 zzyl 的 nursing_project 表 | 不重启
```

### 3.2 批准规则

1. **FIFO**：按提交时间排序；同一资源同一时刻只批 1 人；**不插队**。
2. **时长**：默认窗口 **10 分钟**；队列有人等待时给 **8 分钟**；单次上限 **15 分钟**（超长任务分段申请）。
3. **回执**：批准时回编号 `DQ-YYYYMMDD-NNNN` + 资源 + 到期时间；编号从 `DQ-20261125-0001` 起按序递增。
4. **不同资源可并行**：如 A 占浏览器、B 占 MySQL 写互不冲突（都要登记）；但同一资源必须串行。
5. **不扩权**：批准只覆盖声明的资源与时段；执行中需要额外资源，须补充申请（资源空闲可当场追加批准）。

### 3.3 执行纪律

- 启动前先核实资源空闲（web-control 会核查并将结果记入日志）；发现资源被他人占用立即反馈，不许硬抢。
- 严格按批准目的执行，不做无关操作、不顺手改他人代码。
- 执行中若发现异常（端口被占、服务假死、进程来历不明）立即停止并通知 web-control，不许自行 kill 不明进程。

### 3.4 释放

- 结束**立即**发 `释放`：一句话说明「完成 / 部分完成 / 取消 + 产物路径 + 是否有残留进程」。
- 提前完成建议提前释放，把窗口让给队列；不用的窗口也请释放（已批准未执行也算）。
- 释放后 web-control 核查资源是否真正空闲（端口 LISTEN、相关进程数），再按 FIFO 批下一位。

## 四、超时与回收

| 时点 | 动作 |
|---|---|
| 到期前 2 分钟 | web-control 提醒申请者（send_message） |
| 到期 | 申请者应已释放；未释放先提醒 |
| 超时 2 分钟 | 记入日志（超时）、上报 lead、资源收回并按 FIFO 交下一位 |
| lead 硬截止 | 到点强制回收：先按 PID+路径确认申请者进程，再终止；核对残留并记日志 |

> 回收时只终止**申请者自己在批准窗口内启动的进程**（按 PID + 路径/命令行确认）；不属于申请者的进程一律不动、改为上报 lead。

## 五、冲突与违规处理

### 5.1 违规类型

| 类别 | 例子 |
|---|---|
| 未申请占资源 | 未申请就重启 88/8080、跑浏览器自动化、批量写库 |
| 超范围执行 | 批准 8 分钟实际跑 20 分钟；批准"截图"却重启后端 |
| 越权重启主人服务 | 私自 stop/restart 88/8080/3306/6379 |
| 越权清理进程 | 按进程名批量杀（见 §六） |
| 写非测试数据 | 未经 lead 同意改演示/生产数据 |

### 5.2 核查手段（只读）

```powershell
# 端口归属
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 88,8080,3306,6379 |
  Select-Object LocalPort,LocalAddress,OwningProcess
# 进程命令行与启动时间
Get-CimInstance Win32_Process -Filter "ProcessId=<PID>" |
  Select-Object ProcessId,Name,CreationDate,CommandLine
```

判定依据：端口 LISTEN 状态、进程 PID/启动时间/命令行、是否落在某人批准窗口内。

### 5.3 处理

1. **首次**：记录（`V-NN`）并提醒当事人；
2. **二次**：上报 lead，由 lead 决定处理；
3. **三次起**：lead 决定是否暂停其资源申请权；
4. 查得清记事实，查不清留档不追责（对齐 cpp-control 做法）。

## 六、进程清理纪律（重要，历史教训）

- 只允许：**PID + 路径/命令行双确认** → 确认属于自己批准窗口内的进程 → 终止 → 复核端口与进程状态。
- **严禁**：`taskkill /IM <名字>`、`Get-Process <名字> | Stop-Process` 这类**按进程名批量杀**（历史教训：C++ 端 V-06 按名全量清理误杀了他人实例）。
- 终止前把 PID、启动时间、命令行、路径记入日志；终止后复核目标端口状态。
- 88/8080/3306/6379 的进程**默认不清理**；确认是主人服务的，只能上报 lead 由主人/lead 决定。

## 七、数据库写纪律（R4）

- **只写测试数据**；演示/生产数据（主人演示库、前端展示数据）改动**必须先报 lead 并获同意**。
- 每个写申请须在申请里写清：`库.表`、SQL 摘要、预计影响行数、备份/回滚方式（如 `mysqldump` 单表备份，或 UPDATE 前 `SELECT` 出原值留存）。
- 建表/改表（DDL）与大批量写建议放低峰，先备份。
- 写完后在释放消息里回填**实际影响行数**与验证结果；web-control 记入日志。
- 严禁整库 `DROP`/`TRUNCATE` 测试库以外的对象；严禁改 `sys_*` 系统表之外的主人是演示数据（需 lead 批准）。

## 八、汇报与值守节奏

- web-control **空闲不主动刷屏**；仅在以下情况汇报 lead：lead 询问、申请批/释放处理完、发现违规/异常、需要升级裁决。
- 每个时段（或 lead 宣布收工）写"收工摘要"到日志：DQ 统计、角色使用、成果、超时/违规、收工核对（端口/进程/队列）。
- 公告节奏：**由 lead 在 Web Sprint 任务下发时统一公告**；避免打扰待命成员（2026-11-25 08:47 lead 指令）。
- 待命期：今天上午等老师下发 Web 功能；C++ 端 9:00–12:00 不开发；期间无需主动汇报，收到任务/申请再启动调度（lead 2026-11-25 08:49）。

## 九、快速模板

**申请**（发给 web-control）：
```
<申请者> | <目的> | <资源: 前端88/后端8080/浏览器/MySQL写> | <预计时长 ≤15min> | <影响范围> | <是否重启>

```
已批准 DQ-YYYYMMDD-NNNN ｜ <资源> ｜ <开始-到期时间> ｜ 到期前 2 分钟提醒；结束请立即发「释放」

```

```

**违规记录**（日志 V 表）：`V-NN ｜ 时间 ｜ 主体 ｜ 类别 ｜ 事实 ｜ 处理`

## 十、与 C++ 端 cpp-control 的差异（口径对齐说明）

| 项 | C++ 端 | Web 端 |
|---|---|---|
| 核心排他资源 | 可见窗口 / 模拟输入 / 前台抓屏 / 单实例进程 | 前端 88 / 后端 8080 / 浏览器自动化 / MySQL 写 |
| 构建 | `build-devN` 互不冲突、免申请 | `npm run build`/`mvn compile` 免申请，但后端编译会热重启 8080 → 轻量报备 |
| 数据库 | SQLite 各自隔离库 | 共享 MySQL 3306 → 写必须申请且限测试数据 |
| 长驻服务 | 无（桌面应用单实例） | 88/8080/3306/6379 主人常驻 → 默认不动，重启需 lead 授权 |
| 协议其余部分 | FIFO / 10 或 8 分钟 / 超时上报 / PID+路径清理纪律 / V 记录 | **完全一致** |
